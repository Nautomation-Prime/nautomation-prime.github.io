## Why Nautomation Prime exists

### Where the PRIME Framework came from

Across my enterprise roles, I saw the same pattern again and again: automation got built, the technical work succeeded, and then it stalled. Not because the code broke, but because:

- 🔻 **Nobody could modify it** when requirements changed
- 🔻 **Leadership questioned the value** because nothing measured it
- 🔻 **The "easy" automations had been built**, leaving the hard, high-value work undone
- 🔻 **Teams didn't know what to automate next** because there was no roadmap

The conclusion I drew: **delivering scripts isn't enough. Sustainable automation needs a structured method.**

That's why I wrote the **PRIME Framework**, a five-stage approach for automation that delivers:

✅ **Measurable value** (Pinpoint opportunities based on data, not guesswork)  
✅ **Optimised workflows** (Re-engineer processes before automating them)  
✅ **Production-grade quality** (Implement with safety, testing and documentation)  
✅ **Visible results** (Measure performance with concrete metrics)  
✅ **Team capability** (Empower internal staff to maintain and extend it)

The five stages:

- **P**inpoint Inefficiencies
- **R**e-engineer Workflows
- **I**mplement Solutions
- **M**easure Performance
- **E**mpower Your Team

The framework sits on the **[PRIME Philosophy](../prime-framework/philosophy.md)**: five engineering principles that keep every line of code transparent, measurable, owned, safe, and empowering. It's how I approach automation work, whether on contract or on a project.

## Frequently asked questions

??? question "Can I download the Nautomation Prime tools?"

    No. The deep dives explaining them are free, but the tools themselves are deployed and tailored as part of a contract or project. If you want one in your environment, [email me about it](mailto:enquiries@nautomationprime.io?subject=Tool%20Deployment%20Enquiry).

??? question "Do I need Python installed to run the tools?"

    Not necessarily. Tools can be deployed as [portable bundles](../services/index.md#zero-install-portable-bundles) that run without a Python installation, for restricted enterprise environments where Python may not be permitted. To modify or extend them, you'll need Python 3.10 or later.

??? question "What's the difference between tutorials, deep dives, and the PRIME Framework?"

    **[Tutorials](../foundation/tutorials/index.md)** teach you to build automation yourself with step-by-step guides. **[Deep Dives](../foundation/deep-dives/index.md)** explain production-grade tools line by line so you understand how they work. The **[PRIME Framework](../prime-framework/index.md)** is the method I use to take automation from opportunity to team ownership.

??? question "Can you automate my specific network?"

    Possibly. I take on contract roles and small fixed-scope projects. [Email me](mailto:enquiries@nautomationprime.io) with what you need, or see [Work With Me](../work-with-me/index.md).

??? question "Are the tools locked to Cisco?"

    They are built on vendor-neutral libraries like **Netmiko**, **Nornir**, and **NAPALM**. While designed for Cisco, the patterns and concepts apply across other vendors (Juniper, Arista, Palo Alto, and others), so your skills stay portable.

??? question "How are credentials secured?"

    The tools use native OS credential managers (Windows Credential Manager, Keychain on macOS, pass on Linux). Passwords are never stored in plaintext files or hardcoded in scripts. The CDP Network Audit, for example, prompts you to save credentials to Windows Credential Manager on its first run and uses the stored credentials after that.

??? question "What if I don't have Python experience?"

    The Academy assumes you already know Python basics (variables, functions, loops, exceptions). If you're new to Python, complete a fundamentals course first (Codecademy, Real Python, or similar), then come back. The code is written for clarity, so anyone with solid fundamentals can follow it.

??? question "Is the code production-grade?"

    The tools are built to production standards: error handling, pre-flight safety checks, thread-safe concurrency, and comprehensive logging, following the [PRIME Philosophy](../prime-framework/philosophy.md). As with any automation, test it in your own lab before running it against production.

??? question "What network devices are supported?"

    The scripts primarily target Cisco devices (IOS, IOS-XE, NX-OS, IOS-XR), but the underlying libraries (Netmiko, Nornir, NAPALM) support many vendors including Juniper, Arista, Palo Alto Networks, F5, and more. The patterns taught in the Academy carry across vendors.

??? question "What's in the PRIME Framework?"

    The [PRIME Framework](../prime-framework/index.md) is my five-stage method: **Pinpoint** (identify opportunities), **Re-engineer** (design the workflow), **Implement** (build the automation), **Measure** (show the value), and **Empower** (hand over to the team).
