## How I work on a contract

- **I work inside your change process.** Pre-flight checks, staged rollout, verification and rollback are how I build automation, not optional extras.
- **I document as I go.** Whatever I build, your team should be able to run, understand and change it after I leave.
- **I'm direct about risk.** If something shouldn't be automated yet, or a plan has a gap, I'll say so early.
- **You can see how I think before you hire me.** The [Academy](../academy/index.md), the [Govern](../academy/govern/index.md) standards and the [netpipe capstone](../foundation/tutorials/capstone/index.md) set out exactly how I approach production automation. My public code is on [GitHub](https://github.com/Nautomation-Prime).
